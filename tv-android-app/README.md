# 门店电视大屏客户端

Android TV、小米电视和盒子客户端，最低 Android 5.0。请将 Android System WebView 更新到支持现代 JavaScript 的版本（建议 Chrome/WebView 100 或更新版本）。仅屏幕常亮不代表可绕过厂商后台启动或待机限制。

## 门店使用

1. 从对应源码版本的 GitHub `tv-v2.0.*` Release 下载 `Store-TV.apk`，核对 `SHA256SUMS` 与 `manifest.json`。
2. 电视允许安装未知来源应用，用 U 盘或设备管理工具安装并首次手动打开。
3. 管理后台打开“电视大屏”，设置门店默认内容，从统一媒体库选择图片、视频和音乐，并选择产品、分类与规格。
4. 添加屏幕，选择堂食、外带或其他现有渠道。屏幕可以继承默认内容，也可单独覆盖。
5. 在后台输入电视显示的六位配对码，选择目标屏幕。配对码十五分钟失效，使用一次后不能认领第二台设备。
6. 等待后台显示“已生效”。每台设备报告实际内容版本；“已保存”并不代表电视已收到内容。失联显示状态未知，不代表仍在播放。
7. 一家店指定一台互动设备接收现有订单抽奖结果。其他电视持续展示商品和活动。

每个素材先完整下载并验证 SHA-256，再切换内容；旧版保留为恢复副本。缓存默认上限 1GiB，超限或素材损坏时保留上一完整版本并上报失败。外部素材 URL 不提供离线保障，应先导入统一媒体库。

断网冷启动可以加载 APK 内置页面和完整缓存。到期优惠停止展示；断网超过24小时隐藏全部价格和优惠。系统时间异常或重启后时间无法可信校准时也隐藏价格，恢复联网后重新校准。

## 遥控器与连接

按 Menu，或长按确定键700毫秒打开连接设置。支持方向键和确认键；返回键打开设置而不直接退出。解除绑定需要二次确认并清理身份与缓存。服务器切换后必须重新配对。

默认云端地址由构建参数 `TV_DEFAULT_SERVER` 提供。公网要求 HTTPS；局域网 HTTP 需勾选允许，仅接受 localhost 或私有 IPv4 地址。连接测试检查 `/api/health`。浏览器大屏通过目标服务器 `/tv/` 打开，生产代理必须转发此路径。

## 安装升级与自启验收

正式安装包使用持久 release 密钥；更新时保留相同 applicationId 和签名，versionCode 必须递增。2.0 正式包不能覆盖未知签名的旧 debug 包。已装旧 debug 包的电视需先将门店展示设置保存到后台，再卸载旧包、安装正式包并重新配对；不要把签名不匹配当作升级成功。

同一签名的2.0版本使用覆盖安装，保留连接和缓存。首次安装或强行停止应用后需手动打开一次。小米电视应开启厂商允许的自启/后台运行权限；需在具体电视上验证断电重启、遥控器焦点、音频、视频、屏幕旋转和系统待机。Home 键与电视系统安全策略不由普通应用强制锁定。

## 可重复构建

固定 Gradle8.2.1（wrapper含分发校验值）、AGP8.2.2、Java17、Android34。

```sh
export TV_VERSION_CODE=<大于上一正式版本的整数>
export TV_VERSION_NAME=<显示版本>
export SOURCE_SHA=<完整已验证源码SHA>
export TV_KEYSTORE_FILE=<持久release密钥库>
export TV_KEYSTORE_PASSWORD=<密钥库密码>
export TV_KEY_ALIAS=<签名别名>
export TV_KEY_PASSWORD=<私钥密码>
bash tv-android-app/build-apk.sh
```

正式构建缺少签名、版本或完整SHA时失败，不退回debug签名。GitHub手动工作流运行真实接口和页面测试、校验APK签名，发布同一份验证过的产物；签名凭据使用GitHub Secrets，永不提交到源码。
