# 缺配方历史理论补算与工作台说明精简

报表可显式启用 `backfill=true`，仅对有效订单快照中完全缺失 BOM 的产品，用查询时的当前配方估算缺失部分。原已完整的订单快照不随新配方重算。原快照量、补算量和合计分别返回；补算产品保留配方依据哈希、计算时间、订单数及净份数。已审核的更正、部分历史配方、无法核实的退款及订单不自动重复补算，列入待核清单。

补算是查询时的只读估算，新增代码不调用库存、批次、流水、订单快照、成本或配方写入方法。旧客户端和预警任务不启用补算，继续使用原证据口径。反向冲销快照排除；部分退款按可验证的剩余数量计算；多层加工配方按产出比例和业务基础单位展开。产品级计算失败时不保留部分新增量，避免重复或不完整补算。

工作台默认显示数据、筛选、状态及操作。库存流水中的库存影响说明、补算明细、财务指标和成本更正合并为按需展开的辅助区；保留短“含补算”“待补配方”状态。库存总览、加工、盘点、补货、补货测算、每日耗用、盘点核对及原料应扣减查询的通用说明改为按需展开；库存核查证据导出入口仍保留。实际提交、付款和审核时影响决策的提示保留，不通过全局隐藏文本来精简页面。

验收覆盖补算与未配置清单、加工展开、单位校验、退款、冲销、重复查询、原始输入不变，以及默认折叠和展开可读、原有用途/加工/份数功能、权限提醒、分页、三种语言及桌面/平板/手机。真实数据核查、截图和发布记录保存在本地 output，不写入公共代码说明。

## 报表信息层级

依据 Microsoft Power BI（https://learn.microsoft.com/en-us/power-bi/create-reports/service-dashboards-design-tips）、Tableau（https://help.tableau.com/current/pro/desktop/en-us/dashboards_best_practices.htm）与 Carbon（https://www.carbondesignsystem.com/building-blocks/core/patterns/disclosures）的官方设计指导，采用查询条件、关键指标、可处理状态、明细及按需证据的层级。

每日耗用增加有业务原料数量，保留原有可比较、待补充及有差异指标；点击指标直接筛选明细，补充有业务优先排序。数量单位不同不跨原料求和，不添加无法支持业务判断的装饰图表。查询区间始终可见，覆盖范围及更新时间可展开，区间不一致保持可见短状态。计算规则和重复的材料状态说明不再挤占第一屏，所有原有处理入口仍保留在展开详情中。
