# Private employee runtime transport

This module is not mounted, started, or enrolled by default. It does not create credentials or a new business task store. `Gateway` wraps the existing `host_stdio.py` in a clean `-I -B` process after the pinned raw source verifier. Deployment paths, provider relay URL and backend RPC URL are trusted configuration; none are model tool arguments. The listener is loopback-only. Docker-to-host reachability must be verified in the actual deployment before enabling; these tests prove loopback HTTP, not Docker networking.

The backend client calls `POST /employee-runs` with `EmployeeGatewayEnvelope`: the existing ticket, absolute execution `deadlineAt`, one-execution callback credential, and one-execution model relay credential. The backend must bound the deadline by the grant/task/server expiry before issuing it. The gateway additionally caps execution to 120 seconds. It never receives the MiniMax provider key. Private HTTP must stay on the same machine/trusted private topology; this is not a public HTTP authentication design.

Gateway server configuration supplies one fixed `backend_rpc_url`. Each stdio frame becomes a POST there with `Authorization: Bearer <callbackCredential>` and `EmployeeGatewayRpcFrame {executionId,method,params}`. The backend authenticates that exact execution, enforces the original HostPort schemas/version/ACL, and returns `{result: <existing method result>}`. Allowed methods are recordInput, recordResponse, executeTool, recordOutput and markUnknown. A gateway success is not authority; only persisted backend output can allow completion. A `finished` frame alone fails closed.

Admission SQLite stores only execution ID, a digest binding the entire immutable request (including credential identity), and state/code. It never stores credentials, ticket contents or model prose. Duplicate concurrent admission returns the existing state. A different body or credential for the same execution is rejected. Startup turns all interrupted running entries into unknown; it does not restart children. Lost POST acknowledgement returns `admission_unknown` from the client; callers query GET using the same execution ID and must not generate a new execution to conceal uncertainty. GET 404 is transport absence, not proof that an earlier model action did not occur elsewhere.

Credentials live in process memory and private stdin only and must be redacted by the caller. Child stderr is drained without logging. Unknown callback failure remains in the local admission ledger for backend reconciliation. Backend durable execution records remain authoritative. A deployment supervisor may restart the gateway but must preserve its private journal and must not re-admit unknown work automatically. This change does not implement production supervision or a new platform.

Run `python3 scripts/hermes_employee/test_private_gateway.py`. The fixture uses real loopback HTTP, SQLite, threads and synthetic subprocess frames. It does not run Hermes, MiniMax, production callbacks, grants or employee messages. Configurable paths and endpoint origins allow moving the same private transport to another deployment topology; TLS/private-network policy and source installation need separate cloud verification.
