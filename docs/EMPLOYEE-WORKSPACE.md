# 员工工作台

员工端固定入口为首页、库存、卫生、考勤、培训、个人资料。旧地址继续可用，详情返回所属模块；工资、报销、银行和证件仅在个人资料查看。草稿保存在当前账号会话中，退出清除；照片草稿仅保留在当前浏览器会话内。

## 管理员操作

后台「员工 → 考勤 → 员工审核与迟到累计」(`/staff/attendance/workspace`) 处理迟到申诉、个人档案提报和月度迟到规则。店长和其他员工不能审核或读取私密附件。

迟到规则按门店和月份配置，默认未启用。首次启用只处理启用后的考勤快照，不补罚历史考勤。修改已有规则须先预览影响并明确确认；阶梯金额为累计总额，不叠加每次阶梯。新累计规则取代同月按次迟到扣款。旧记录缺少班次快照时无法可靠还原累计分钟，不用当前排班伪造历史快照。

员工打卡记录实际原始时间、有效时间、班次起止时间快照、班次开始日期、完整迟到分钟和豁免状态。09:01 对 09:00 计一分钟；09:00:59 计零分钟。无有效排班标记待核对，不按固定时间罚款。

申诉批准后真实时间保留、分钟豁免。未发工资更新关联扣款；已发工资保留原单，下期生成返还。冻结、金额冲突或并发变化进入「工资待处理」，管理员填写说明后重新核算；返还期冻结时可选择未冻结月份。不会让工资处理失败阻止员工考勤或保存已批准申诉。

KTP、银行和个人资料提报不直接替换正式档案；批准后更新。学习完成仅是服务器保存的自报记录，不能自动产生正式考核通过或奖励；旧本地进度需主动导入。

## 数据和发布

新增记录使用现有 Config 表的受保护命名空间 `employee.workspace.*`，包含快照、规则及版本、申诉、资料版本、学习进度、提醒、订阅和发送状态。不需要破坏性 schema 迁移。普通配置接口不能读取或修改此命名空间。

私密附件位于 `UPLOADS_PATH/.employee-private`，依赖持久化上传卷。通过鉴权下载接口访问，公开 `/uploads` 路由拒绝该目录。不要公开 VAPID 私钥或附件目录。

先部署 API，再部署后台及员工端。POS 前端、安装包和升级流程不变。后端一分钟轮询提醒及工资待处理，启用前没有新罚款。

## 推送与验收边界

Web Push 支持班次前30分钟、卫生任务前15分钟、新任务及审核结果。提醒持久化去重，源任务失效则取消，发送最多三次、失效订阅停用。发送失败不影响业务提交，App 内提醒保留。锁屏只有状态和入口，没有工资、处罚金额或证件内容。

iPhone 需支持 Web Push 的系统、添加到主屏幕、在 App 内授权通知；Android 使用支持 Web Push 的浏览器。普通 iPhone 浏览器标签页无法保证收到推送。真实 Android/iPhone 的锁屏送达与相机扫描需要实际手机授权验证，模拟窄屏和服务端假推送不代表手机验收通过。

回归脚本 `tests/stoploss/employee-workspace-http-check.cjs` 使用全新隔离 SQLite 或 PostgreSQL 与真实 JWT/HTTP 路由；验证分钟、午夜、重复/并发、工资差额、私密权限、申诉和冻结返还、资料审批、学习进度、规则预览及推送去重。推送传输替身只在此脚本内，绝不向真实手机发测试消息。CI 两种数据库执行此脚本。生产核对只读，不制造工资、库存、考勤或个人档案记录。
