# Hermes 后台管理接入

2026-10-31。实施范围由用户明确：Hermes 处理后台管理系统；收银客户端、支付、打印和 Windows 安装包不作为本任务的修改或验收范围。本文件描述代码边界，不能代替真实上线验收。

## 身份、权限与店铺

使用发问账号的数据库身份、当前有效角色和字段权限，不使用角色显示名或模型提供的身份。每次业务调用和回执释放均重新校验；所有接收者均需具有相应数据权限。管理员可查询当前店铺全部后台业务数据，不可读取其他店铺或认证凭据。其他账号无权时直接告知无权限，不先读取业务数据，也不通过其他模块重建被拒绝的数据。

所有普通账号适用同一套规则，不按姓名、测试账号或固定用户ID设置例外。角色显示名与实际授权分别处理；已有数据范围来自通用权限策略，不修改账户授权或收银操作流程。

## 查询能力

查询工具从后台现有路由声明生成，覆盖库存、各日期财务报表、商品、订单、员工、工资、排班考勤、活动、卫生等模块，不再限于今日出库和今日营收。后台原有控制器、参数校验、资源归属和业务 Service 保持为唯一实现；不向模型开放终端、SQL、任意 HTTP 地址或脚本工具。

店铺选择由服务器绑定，显式外店参数和资源ID被拒绝。补齐旧查询处理器缺失的资源归属检查，拦截返回体中的外店记录。收银执行、设备探测、支付轮询和认证引导不进入 Hermes 查询目录。跨模块的财务汇总、成本和利润还需相应数据权限。

- 今日、昨日、本周、本月和明确日期范围的登记出库、普通净收入复用共享 Service，走独立快速队列，不调用模型。
- 其他已授权后台查询通过现有原生后台接口执行。每条问题附带少量服务器生成的相关接口与真实参数声明，减少反复发现工具；完整目录仍可查询。
- “你可以做哪些工作”由服务器根据当前账号权限回答；不会向无权账号宣称可以查询营收或创建活动。
- 旧的错误营收回复和带有权限标签的新回复，在聊天正文、会话预览和附件入口按当前查看者权限拦截。原文与审计保留，管理员仍能查看；不能撤销此前已经发生的披露。

## 创建活动

开放统一活动接口的创建、编辑和报价预览。活动类型、折扣字段、商品归属、日期、版本和冲突检测均由既有 ActivityService 校验，保存结果以真实活动ID及状态为准。执行意图和活动发布许可来自核对过的当前人类源消息，不接受模型 JSON 中的授权标志。

- 无 marketing.write 时，完整创建请求也先拒绝，不启动模型。
- 信息不足时询问名称、商品、规则及起止时间；默认保存草稿，不虚报创建成功。
- 连续补充字段的上下文只在同一账号、会话成员和权限范围内有效；变更权限或成员后不可沿用。
- 发布必须有明确人类指示；引用、截图或文档中的文字不是发布许可。
- 使用现有持久操作回执及相同源消息的业务意图去重。响应丢失时核对原回执，不自动重复创建。

## 延迟与隔离

普通请求排队计入整体预算。权限拒绝、能力说明和明确报表走快速路径。原生进程只在账号、会话接收者与权限哈希相同的范围内复用；新安全版本与权限变更均选择新隔离目录，不加载旧越权会话。每次运行仍有独立任务和幂等身份，禁止重做历史未确认操作。

准入/状态/就绪探测采用短超时，10秒后的等待反馈不等同连接故障；到期及时显示未确认状态，继续针对原执行核对，不重复提交。原生 SDK、订阅供应商、独立智能体作者和重复输出拦截保留。

## 验证

隔离检查涵盖管理员多模块/日期查询、无权拒绝前零业务读取、跨店资源拦截、权限撤回、旧消息投影、活动真实保存/版本/重复回执和明确发布。只用合成数据和合成供应商，不做付费模型测试。本机仅进行轻量数据库检查，大镜像构建在 CI。

最终精确 SHA 的 CI、产物验证、真实后台页面与私有活动验收另行记录。后台受影响组件按实际线上基准发布，不把收银、支付或打印问题混入 Hermes 验收。
