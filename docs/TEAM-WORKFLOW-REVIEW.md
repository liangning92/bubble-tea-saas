# 员工来信工作流：人工许可与审批入口

基于已上线 a63618a18542a92f24507637a66de0e33779592f，复用原工作流和任务接口；没有新增执行权限、生产消费者、模型调用或数据库迁移。

## 使用入口

- 设置 → AI设置 → 员工来信处理许可：仅真实管理员可见，选择本人已加入的频道和允许处理新文字的员工。开启前重新读取连接，须与本次审阅的配置版本和验证版本一致。active policy 保存要求 expectedAiConfigVersion / expectedAiCheckRevision，并在现有 ai-budget 锁和频道事务内核对当前 ready 回执后保存；没有证明、旧版本或未决连接均拒绝。暂停/禁用不要求这些证明，模型异常时仍可停止。消费者执行契约和原权限边界保持。
- 员工 → 团队沟通 → 当前频道 → 任务与纪要 → AI 来信待办：当前管理员读取自己的工作流记录，人工审阅或修订回复；任务审批时填写接收时间、完成期限、证据要求和标准，员工和验收人由原消息及当前身份固定。
- 任务下达后使用原任务区完成员工接收、本人证据、主管退回/验收；不把 reviewed 草稿状态解释为任务完成。
- 中文汇报读取原 export 接口，支持继续读取下一页。陈述、AI 草稿、可能费用、任务证据和主管结论继续由服务端区分；可以手动复制给老板。没有向 Codex 父对话自动推送。

## 失败与恢复

审批请求先记录于当前浏览器会话存储，按用户、门店和频道隔离。响应不明时锁定新的审批，刷新后仍可人工使用原 requestId 和原内容核对；不自动重发。存储不可用或记录格式/频道不符时停止提交。已知版本/权限错误保留编辑内容并显示错误；记录变化后禁止批准旧表单。

许可保存结果不明时锁定表单，刷新后保留未决提示。管理员须明确重新读取已保存状态后才可继续，不自动重放开启请求。暂停/禁用使用已保存的员工范围，不把尚未保存的勾选误当作停止范围。

结果不明保留逐尝试费用风险。人工批准新模型尝试须同时确认内容和可能重复计费，最多三次由既有服务端限制；核对已保存结果不调用模型。界面只轮询记录，不启动消费者；页面关闭、Codex 结束会话都不能解释为后台仍在处理。父对话鉴权桥、持续消费者和生产许可仍需另批授权。

原聊天附件、outbox 存储 scope、消息和任务 UI 保留；员工端不加载本次后台审批组件，shared 组件只增加可选的后台渲染入口。审计查看或非管理员不会看到入口。
