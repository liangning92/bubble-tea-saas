# 员工库存操作记录与跨日补录

## 行为

- 入库、出库、采购页面下方直接查询对应记录；盘点保留进行中、待审批任务，历史结果在下方分页查询。
- 默认雅加达当天，可按日期范围、物料查询，每页 20 个业务单据；原料汇总覆盖全部筛选结果而非当前页。
- 员工查看本门店全员操作；出库沿用已登记库存操作原因范围，不包含销售扣料、销售估算、估算冲销或盘点自动校准。
- 出入库支持实际发生日期，采购有独立采购日期，收货可选择实际入库日期。保留系统录入时间；不重算历史库存、成本及已结算报表。
- 补录此原料预选原料与日期，不复制数量；未提交表单需要员工选择是否放弃。查询、翻页、刷新不清空表单；保存后留在当前页更新记录。
- 历史查询旧地址继续可用。盘点历史只读，保留原来的进度指标、实盘明细、未盘项筛选和退回历史。

## 数据与兼容

新增 nullable DATE 字段：StockInLog.occurredOn、StockOutLog.occurredOn、PurchaseOrder.purchasedOn。旧记录不回填推测日期，按雅加达录入日期回退显示。

迁移：server/prisma/migrations/202610290001_inventory_operation_dates/migration.sql。仅新增字段和索引，旧应用可忽略。API 发布前备份并应用迁移；不得运行会删除历史数据的 schema 重建。

只读接口 GET /api/inventory/operation-records：kind=in|out|purchase|count，startDate/endDate（YYYY-MM-DD），inventoryId，page。范围由已登录门店绑定；返回 list/summary/total/page/pageSize/timezone，稳定按业务日期、录入时间和身份排序。分页和汇总在同一数据库读取快照内执行。

原有提交接口增加可选 occurredOn/purchasedOn，保持既有调用兼容；日期参与出入库提交幂等指纹。

## 验证

- API 与员工端类型检查通过；员工端三语检查通过；员工端生产构建通过。
- PostgreSQL/SQLite 隔离回归结构均能生成；SQLite 临时库将原生 DATE 映射为可空 DateTime，不改变正式 PostgreSQL 类型。
- 真实隔离 PostgreSQL + 真实 HTTP 权限链检查通过：253 条完整分页、汇总、雅加达边界、本门店全员可见及跨店隔离、非法日期、双日期、重复出入库与采购收货、未收货采购不入库、盘点只读。
- 隔离测试通过 with-docker-test.py 执行；失败批次与成功批次均确认清理完成，不使用正式凭据、正式数据卷或正式数据。
- 构建后员工页面合成接口测试通过：四模块记录区、下方布局、保存并刷新、保留未提交表单、补录预选、分页、错误重试、空结果。390/768/1440 布局及三语截图保存在 output/inventory-records/synthetic。
- UI 检查保留入库、出库、采购、待收货、库存列表、盘点任务、审批结果、进度指标、历史实盘与退回记录；未修改一级导航。日期控件沿用现有本地化组件。

真实员工端当前需要有效登录会话。以上合成截图和自动化测试不能替代真实业务页面及上线后的验收；不得据此宣称真实业务补录或上线验证完成。正式环境不得创建测试采购、出入库或盘点交易。
