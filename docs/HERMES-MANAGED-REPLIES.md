# Managed conversations and visible replies

When the saved Hermes setting enables all channels, an enabled management conversation automatically joins the native Hermes employee runtime on its next human message. The existing management consent, real active audience, configured agent, owner, channel permissions, grant expiry and explicit pause remain authoritative. No text keyword chooses a restricted legacy coordinator. An administrator asking Hermes a question does not implicitly take over the conversation; the explicit takeover control still pauses it. The agent is recorded as an actual channel member with a native assigned task and source floor; historical blocked requests are not replayed.

Adding an authorized conversation extends the same grant's staff/channel scope. It changes no executable action, revision, expiry, or user settings. In-flight turns tolerate only additive scope changes; action changes, removals, revocation and expiry retain their checks. Direct human conversation lookup includes automatically joined agent conversations to avoid duplicate contact threads.

Sensitive data follows the current audience's saved account permissions on business tool results and publication. The question itself remains available to the model, so it can explain unavailable data, ask clarifications, or help with allowed work. The sponsoring administrator does not lend financial access to an employee.

A failed or timed out persisted runtime with no delivered response publishes one fixed informational reply through native agent identity and current channel/task/output checks. It explains the failure or permission issue without exposing raw errors or echoing private content. A deterministic request and persisted receipt prevent duplicates after restart. No model call or business operation is retried by this publisher. Explicitly disabled/revoked messaging authority still stops publication.

Validation: `python3 scripts/with-docker-test.py -- python3 scripts/test-employee-managed-replies.py` uses disposable PostgreSQL, native communication and receipts, synthetic gateway/model only, and cleans the owned batch. It covers enrollment, unrestricted financial vocabulary, pause, direct lookup, scope authority, exact failed-source provenance, idempotent failure messages and refusal after revocation, plus existing runtime, orchestration and business regressions. Production acceptance uses the existing administrator-private Hermes conversation; no test messages are sent to real employees.
