# 电视大屏部署与恢复

## 数据与版本

电视屏幕、设备及配对会话使用 TvScreen/TvDevice/TvPairSession。商品、价格、活动和素材复用现有门店数据。旧全局JSON只作为明确选择归属的导入源，不再自动创建默认屏幕。导入前备份JSON，重复导入同屏幂等，不能跨店重复认领。导入后待机，重新选择本店产品并配对。

PostgreSQL部署前使用现有数据库及媒体备份脚本，隔离恢复验证后，事务执行 `server/prisma/migrations/20261014_tv_signage/migration.sql`。只添加表和索引，无数据删除。应用启动核对所需表，迁移缺失时拒绝接受流量。SQLite由启动升级器备份后事务创建表，校验完整性；不替换营业数据库。

镜像必须来自同一源码的成功CI和对应Docker验证产物。部署前重新读取API和后台SHA，保留运行中的Compose叠加链、JWT、数据库卷和上传卷。只替换API和后台，不替换POS、员工端或Windows安装器。

现有正式上传卷为 `/app/uploads` 的实际挂载；禁止使用新空卷替换它。API运行目录应为 `/app`，旧JSON导入目录由 `TV_LEGACY_DATA_PATH` 指定并持久化。基础Compose示例的卷名不能替代实际线上卷。

## 播放与代理

后台、API均需正确提供 `/tv/`；后台Nginx代理至API，上传沿用 `/api/media` 已验证限制。大屏脚本外置，保留Helmet CSP及认证边界。Native APK内置相同播放器，不依赖首次在线下载HTML。`scripts/sync-tv-player.cjs` 同步打包源码，接口与页面测试覆盖新链路。

设备连接使用 `X-TV-Device-Token`；配对状态查询使用 `X-TV-Pair-Secret`。代号和URL不能代替凭证。设备删除或撤销后，在线设备清理缓存重新配对；离线设备将在恢复联网收到撤销响应后清理，远端无法即时删除断网设备本地文件。

配置发布记录目标版本。设备下载完成后报告生效版本，后台每10秒刷新状态。失败时保留旧版本；心跳错误可以区分下载失败与失联。营销价格复用POS候选选择器，条件优惠明确展示条件；缺价产品不造价。

## 发布验收与回滚

核对公网 `/health` 的 sourceSha、tvSignage能力和数据库状态；未登录屏幕修改返回401，旧代号不能公开读取内容。验证管理页、配对、同店素材、版本确认和样例页面，不向生产创建测试交易。

保留部署前镜像和Compose快照，失败时单组件恢复旧镜像；新增表供旧版忽略，不回滚营业数据。生产备份恢复到隔离库演练，不能覆盖活动库。电视APK保存签名证书指纹、校验值、源码SHA和versionCode。新版本安装/自启实机验收未完成时必须记录为未验证，不能把浏览器测试称为电视实测。
