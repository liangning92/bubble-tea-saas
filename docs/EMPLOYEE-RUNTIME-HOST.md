# Employee execution host: isolated integration status

This increment adds private, default-disabled host ports and a child-process adapter. It is not a production registration, a new grant, or proof that dot receives events. Production inventory task rework remains the manager's operation.

## Persisted execution

The existing Config store holds an execution and its compartment pointer. The task, fresh server grant, current channel audience/access-policy hash, exact authorized sources and their fingerprints are bound before execution. Concurrent turns acquire the existing transaction lock; input reservation commits before the model HTTP send. No retry of a reserved/unknown turn is admitted. Recovery records an interrupted execution; it does not send another model request.

Each complete response precedes tools. A tool must match that persisted response's call ID, ordinal, name and parsed arguments. The current catalog reads one actual employee-visible message, reads the same native employee task when authorized, and sends a natural operational reply. Native send and its immutable tool receipt share one database transaction. Native request idempotency, source sequence, reminder/outbox and audit remain in the existing implementation. Tool output enters the next model request exactly; caller/body claims of sources or approval do not authorize anything.

Source ACL rejects manager agent-task records, arbitrary memory, unverified public-SOP labels and all attachments. Operational source reads require their own read scope. All real recipients and source authors must still be active, bound and eligible. A secondary sensitive-text tripwire is not a claim of perfect semantic detection. No finance, payroll, arbitrary SQL, inventory adjustment or authority tools exist here.

## Actual Hermes boundary

The child adapter uses explicit configured paths; no Mac path, startup service or public Hermes listener is embedded in the host. It reuses the reviewed raw-tree verifier before importing Hermes, starts Python with isolated flags and a minimal environment, binds an exclusive empty HOME/profile/session, and communicates over private stdio. Credentials supplied to the child must be short-lived scoped relay credentials; a raw MiniMax/provider key must not be copied to Hermes. No production relay enrollment is added by this increment.

Initial system bytes must match an explicitly approved assembly or the pinned isolated-system template. Template normalization replaces only exact host-issued execution paths and strictly formatted clock/OS lines; all other prompt bytes remain hashed. Later requests must equal prior persisted messages plus the exact observed assistant response and backend tool results. The pinned Hermes null-to-empty assistant-content serialization is explicitly accounted for. Final output must equal the final recorded provider response. `finished` from the child alone grants nothing.

- API TypeScript build passed.
- Nine real disposable PostgreSQL scenarios passed in batch `bt-test-5c3fcc44894f` and were cleaned. They use synthetic provider turns, not a real Hermes child or model.
- 36 CI planner tests passed; the new domain invokes the dedicated temporary-PG runner.

Its correction and independent acceptance are required first. The existing raw-source verifier is additional defense, not a substitute for closing this upstream defect.
- No new production operation, employee message, real model call, plugin connection, grant, Events subscription or inventory task rework was performed for this increment.

Still required before delivery: integrate the Hermes environment correction; actual child + persisted host + native tools combined tests; parent independent review and exact candidate CI; authoritative production task resolver and scoped model relay wiring; manager-visible fault projection and host registration. The existing work-item tools remain separate from the current runtime catalog; this does not yet claim full task assignment/review or published-SOP execution through the child.

Cloud migration requires configured Python/Hermes installation and its reviewed source hash, a private execution-root volume, the existing durable database and instance ownership, the scoped model relay and authenticated manager/executor routing. OAuth/Events and OS Push are separate verified boundaries. Moving paths alone does not establish them.
