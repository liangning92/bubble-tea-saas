# 统一库存盘点工作区

用户要求将盘点调整、盘点审核整合。现有“盘点调整”是库存流水筛选，正式审核生成 reason=count_adjustment；流水未识别该原因、没有盘点单链接，盘点页缺状态筛选，临时盘点在后台还缺提交按钮。
学习：Odoo 官方盘点流程将实盘数量、差异、应用调整和历史追溯关联为同一工作流：https://www.odoo.com/documentation/19.0/applications/inventory_and_mrp/inventory/warehouses_storage/inventory_management/count_products.html 。本项目已有创建/实盘保存/提交/审核/查询接口、审核差异流水和 countId/countItemId，复用现有后端。
方案：统一“库存盘点”入口，按状态查询；同一盘点单录入、提交、审核及查看已入账调整结果；库存流水保留记录并链接回原盘点单和物料行，取消重复的盘点调整标签；审批权限沿用现有角色/授权规则。修正盘盈流水双负号，保留流水中的审批人和差异说明。仅前端修改，不改数据库、后端库存计算或正式数据，不构建、不发布。

验证：Admin 类型检查通过；中/英/印尼三语言翻译检查通过（仓库原有硬编码警告未新增处理）。本次差异选定范围只涉及 admin，59 项相关单元测试通过；3 组已有盘点权限/观察边界/库存单位审计共 18 项通过。实际 React 页面、项目真实样式和隔离 API 边界回归通过：状态筛选、实盘保存、临时及周期盘点提交审核、一次审核后显示只读调整结果、刷新保留盘点单、历史调整、库存流水回链到物料行、不可访问单据、创建后进入单据、员工/只读授权、手机录入和三语言。手机表格采用横向滚动，避免表头被挤成竖排。没有操作线上业务数据，也未运行正式构建/发布。测试截图：/tmp/inventory-count-workspace-desktop.png、/tmp/inventory-count-workspace-mobile.png。
