# POS 收银风险核查强化

- 人工 F6 开箱填写 2–200 字原因；先持久化请求，失败则不发硬件指令。POS 测试与后台测试走同一审计发送函数。发送后结果记录失败也不重复脉冲。
- 现金结账自动指令关联订单，和人工/测试指令分开；所有结果仅代表请求或传输状态，实际钱箱开关未知。
- 商品减量/删除保留商品、数量和修改前购物车快照。未结账清空保留原有明细；已结算清空不算异常。
- API 按登录门店和员工保存记录，人工请求不接受客户端 info 降级。同员工 15 分钟内第 3 次及之后人工/测试请求或未结账清空升级 critical；正常自动开箱为 info。已发送的结果为 info，避免同一请求产生重复行为提醒。
- POS 预警新增所选时段按员工汇总，可点击次数筛选，并清除员工筛选。统计独立于日志分页，原导航、四项指标、未入账凭据、当前未结账购物车、日志筛选/打印分类/分页均保留。三语支持，卡片和按钮可换行。
- 不制造钥匙检测、出杯检测或违规结论。旧 POS/离线未上传记录的覆盖未知，零记录不能证明零风险。人工开箱审计提交失败时需恢复连接；自动结账不以附属审计上传为支付成功条件。
- 保留现有撤单与退款权限、审批和交班差额流程。本改动不自动变更库存、杯数、资金、退款或审批政策；凭单制作、钥匙保管与盘点仍需门店执行。

验证与发布证据保存于工作区 `output/pos-risk-controls-20261019`。门店 Windows 实机和真实钱箱物理状态不能由 Web/CI 代替验收。
