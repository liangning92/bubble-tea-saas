# 门店运营计划最小闭环

本批仅独立分支和隔离验证，不合并、迁移生产、启用自动消息或部署。基于 master 671d4177b061d2bb0bfb5b693a15028f2e7a3d84；只读线上 API 60f91daa、Admin/Staff ab4a756e、POS 8989b629。保留 master 已有 POS 风控修改。

## 分工和范围

Dot 在主对话准备结构化计划，管理员通过现有频道导入、核对责任人和时间并批准发布。MiniMax 只能辅助解释、追问或提醒，不能改变任务状态。员工本人接收、提交本人消息证据；指定主管逐项验收或退回。管理员检查升级清单，导出带证据编号的中文结果给 Dot，再将调整方案作为新版本审批。

不建立新凭据、外部回调或持续授权。结果回传是管理员下载并主动交回主对话，不宣称 Dot 自动获得门店实时状态。复用 Config 的店铺隔离记录、现有频道与任务状态机；不新增数据库表或迁移。计划暂停时阻止新发布和执行，仍允许授权主管取消未完成项并写明理由。修订前必须取消或完成上一版所有任务，保留快照和历史，不静默改动员工已接收的任务。

## 先行验收矩阵

| 编号 | 场景 | 必须结果 |
|---|---|---|
| A1 | 导入严格结构的计划；缺负责人、截止时刻、证据或验收标准 | 草稿私有且有版本；缺字段、非法日期、无权成员或未知字段拒绝；不创建任务或消息 |
| A2 | 管理员核对当前频道成员并明确批准发布 | 原子生成已批准任务；同请求重试不重复；成员变化和版本冲突阻止发布 |
| A3 | 员工确认、提交；他人、跨店、退出频道及新加入成员访问 | 沿用权限和历史下限；已读不等于接收；只允许本人证据 |
| A4 | 验收／退回 | 仅指定且有权限主管操作；完成需确认验收标准并填写说明；模型不能操作状态 |
| A5 | 未接收、逾期、提交待验收、责任人离开 | 管理员人工扫描形成去重的升级记录；状态变化后标为已解除；不自动发送消息 |
| A6 | 计划内 AI 解释／追问／提醒 | 仅已批准当前版本；提示取自批准快照，不允许自由扩大任务；模拟模型；发布前再次核对计划、任务和成员；生成不等于发送 |
| A7 | 暂停、恢复、修订 | 暂停拒绝执行和计划内 AI 发布；恢复须人工；修订需先关闭旧任务；版本与审计保留 |
| A8 | 请求丢失、重复、并发与失败 | mutation 请求幂等且 payload 冲突拒绝；乐观版本锁；错误可见；模型结果不明不自动重试，可查询原请求 |
| A9 | 导出中文结果及再规划 | 服务端确定性统计，员工陈述、证据、主管结论分开；含计划版本、任务状态、升级记录；无密钥、无附件外发；导出不自动分享 |
| A10 | 管理员真实页面结构与员工任务布局 | 现有聊天、纪要、任务和 AI 设置保留；桌面／平板／手机无横向溢出；只在隔离合成账号验证新写操作，生产未验证须明确 |

## 本批自动化边界

自动消息固定关闭。升级扫描由管理员点按，没有后台定时器；扫描不调用模型。管理员生成计划内草稿仍须明确同意外发文字并逐条批准发送。现有 MiniMax 配置与不限额选择保持不变。新增任务提醒调度、频道／时段授权、失败重试队列或 Dot 受控连接须另行设计审批。

## 发布前须另行确认

预计影响 API、Admin、Staff；无 Prisma schema 变更，但会在既有 Config 表写入计划、快照、幂等请求及升级记录。上线前仍需核对最新线上版本、备份与回滚兼容性，复核数据量上限与权限。生产数据库变动、自动化启用和上线不在本轮执行。

旧 API 不认识计划暂停、指定主管和验收确认字段，不能在存在未关闭计划任务时直接回退到旧 API。发布前需准备保留本批任务守卫的回滚镜像，或先由人工关闭全部计划任务并核实后再回退。前端旧版提交缺少验收确认时，新 API 会拒绝；不可为兼容旧页面放宽服务端守卫。

单频道最多 50 份计划、合计 200 个任务；单计划最多 20 项、100 次操作版本、1000 条升级记录；达到上限明确报错，不静默截断。暂未实现归档及请求记录保留期限，扩大试点前须规划容量。证据要求与验收标准是人工核验文本，系统不自动判图片或业务结果合格。

## 管理员操作和主对话交接

入口：员工→团队沟通→本人参与的频道→运营计划。新建表单或“从主对话导入计划”只保存草稿。管理员核对当前成员、负责人、指定主管、时区、证据和标准，填写说明并勾选批准，才创建任务。员工端沿用原任务操作。升级检查、计划内模型生成、草稿发送均须人工点按。

调整时先完成旧任务；或者暂停计划并说明取消未完成任务，再修订、重新核对和批准。旧任务及其来源版本不覆盖。

导入正文协议如下，人员 ID 与时间仅为占位示例，管理员必须在载入后的表单中选择真实频道成员并核对；不会自动映射员工，也不是执行授权：

```json
{
  "schema": "team.operations.plan.v1",
  "title": "开闭店卫生检查",
  "objective": "按现行 SOP 收集记录并由主管验收",
  "reviewerId": "REVIEWER_STAFF_ID",
  "items": [{
    "key": "opening-check",
    "text": "Periksa kebersihan sebelum buka sesuai SOP yang berlaku dan kirim hasilnya.",
    "ownerId": "OWNER_STAFF_ID",
    "acceptByAt": "2026-10-21T08:00:00+07:00",
    "deadlineAt": "2026-10-21T09:00:00+07:00",
    "evidenceRequired": "Checklist dan pesan hasil dari pelaksana; foto bila diwajibkan SOP.",
    "acceptanceCriteria": "Atasan memeriksa semua bagian sesuai checklist yang berlaku."
  }]
}
```

接口沿用现有登录会话，无新增密钥：

- `POST /api/team/channels/:id/operations/import`：请求编号、expectedVersion、可选 planId、上述 content。
- `POST /api/team/channels/:id/operations/:planId/actions`：publish／pause／resume；请求编号、版本和说明；发布／恢复必须 approved=true。
- `POST /api/team/channels/:id/operations/:planId/scan`：人工升级检查，重复请求去重，不发送消息。
- `GET /api/team/channels/:id/operations/:planId/export`：`team.operations.result.v1`，含计划各版本、确定性统计、员工提交、消息证据、主管结论和最近升级检查时刻。

管理员下载结果后主动交回主对话，Dot 才能根据该快照调整后续计划；导出文件不是持续连接，也不自动上传模型。计划内 AI 使用原草稿接口的 operation 参数绑定计划和任务版本及 explain／followup／remind 目的；服务端从已批准快照构造要求，拒绝混入自由指令或员工消息。发布草稿前再次核对范围、任务状态和成员。
