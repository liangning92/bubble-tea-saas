# 后台管理系统中文语言界面显示英文/混合语言问题

## 问题描述

在后台管理系统 (client-admin) 选择中文语言时，财务、库存、会员、设置、配送等大部分模块依然显示英文或混合语言。

## 影响范围

- `client-admin` 后台管理系统各主要页面（财务报表、库存与BOM、会员系统、小票模板设置等）。

## 根因分析

1. **命名空间错位 (Primary Bug)**：`client-admin/src/i18n/zhMissingFallback.ts` 中使用了 `i18next.addResourceBundle('zh', namespace, translations, true, true)`，将补丁翻译分别注册到了 `announcement`, `finance`, `inventory` 等独立命名空间。但组件层调用 `useTranslation()` 时未传参，默认读取的是 `'translation'` 命名空间。这导致 i18next 无法匹配中文，自动退回使用英文 (`fallbackLng: 'en'`)。
2. **Key 缺失 (Secondary Bug)**：在 `client-admin/src/i18n/index.ts` 中，英文包共有 3,091 个 key，但主中文包直接缺失 1,662 个 key。除了 `zhMissingFallback.ts` 中的 1,410 个 key 外，仍有 418 个 key 完全未包含。

## 修复方案

1. 修改 `zhMissingFallback.ts` 中的 `initZhMissingFallback()` 函数，将其以 Deep Merge 方式直接合并注入到 `'translation'` 默认命名空间中。
2. 将剩余 418 个缺失的英文 Key 翻译为中文并完整补充至 `zhMissingFallback.ts`。

## 验证方式

使用 Node.js 脚本动态解析与初始化 i18n 实例，测试 `i18n.t(...)`，验证 `client-admin` 中 100% 的英文 Key 均能映射出正确的中文。

## 预防措施

规范所有新增组件与 i18n 语言包的结构，新增多语言条目时确保同步更新 `id`, `en`, `zh` 三种语言，且统一存放在 `'translation'` 默认命名空间或显式声明命名空间。
