# Administrator corrections for manual inventory entries

The stock ledger now offers administrator-only correction/history actions for original manual receipts and manual issues/losses/expiry/other outs. Purchase receipts, sale estimates, processing, count adjustments and generated correction rows cannot be independently edited; generated rows link back to their original manual entry.

Corrections retain the original row, append a signed reversal and an optional replacement, and retain the whole revision chain: original/current material, inventory unit, quantity, total IDR amount, notes, correction reason, administrator identity/time and before/after balances. Cancelled sources cannot be cancelled twice. Administrators may correct the current replacement again through the original source. A mandatory reason, expected revision and durable request UUID protect against accidental resubmission, lost responses and competing administrators. Generic configuration APIs cannot read/write the internal correction receipts/history. A separate finance audit event is stored in the same transaction. Materials referenced by correction/reversal ledger entries cannot be deleted, so deleting a material cannot erase the original or its audit trail.

Physical corrections update carrying value, weighted average cost, receipt/consumption batches and affected BOM/product costs together. An outgoing reversal restores captured batch allocations, or an explicitly identifiable restoration batch for older manual outs lacking allocations. Internal issues change registration quantities/value only, preserving whole-store stock and average cost. Neither corrections nor receipt reversal execute a payment/refund or change bank/cash evidence. Existing sale/order cost snapshots remain frozen; derived recipe/product costs apply prospectively.

All quantities are explicitly entered in the selected material's inventory unit; changing material clears quantity and total amount to avoid unintended mass/volume conversion. Zero IDR is an explicit amount. Historical zero-value receipts without valuation evidence require the administrator to verify and select recorded free value versus unpriced/current-average reversal basis; this choice and exact resulting balances are audited.

Safety boundaries: a changed/cancelled original, foreign-store material, invalid quantity/value, insufficient stock, impossible remaining value, missing/consumed receipt batch, later calibrated count or active/pending count prevents inventory/value changes without partial writes. Historical ledger mutation and guessed consumed receipt revaluation are not performed. Notes can still be corrected without inventory/value effects. Records blocked by subsequent consumption/counting need a physical reconciliation and valuation review rather than blind rollback.

UI retains the four KPIs, original tabs/filters/export/registration controls and navigation. Adds an action column and a responsive correction/history dialog; export includes correction source, role and reason. Signed reversal/replacement amounts flow through the existing ledger KPI calculations. Costs broadcast the existing refresh event. English, Chinese and Indonesian copies cover validation/conflict and safety errors.

Validation: synthetic SQLite and PostgreSQL tests exercise real Express/auth/Prisma plus actual ledger triggers, source preservation, signed net amounts, quantity/material/value changes, cancellation, lost-response retries, simultaneous administrators, cross-store/role denial, consumed/count guards, note-only correction and BOM recosting. Browser tests use the real dialog with a synthetic transport for failed saves, retry identity, conflict/reload, validation, history and three languages across desktop/tablet/mobile. Production verification uses existing logged-in sessions; no invented stock transactions are inserted into production.
