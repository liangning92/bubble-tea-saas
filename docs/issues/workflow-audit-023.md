# 使用流程全面检查与回归（2026-10-07）

本轮覆盖后台管理、收银端与员工端。测试使用独立生成的 PostgreSQL / SQLite 数据库及合成账户；没有向营业数据库写入测试费用、订单或积分。

## 已复现并修复

| 问题 | 原因与修复 | 验证 |
| --- | --- | --- |
| 支出自定义类别不能保存 | `PUT /categories` 被先注册的 `PUT /:id` 截获；调整注册顺序。保存失败保留输入，成功后更新列表。 | 浏览器添加、刷新、选用并保存费用；模拟失败后重试；两种数据库持久化。 |
| 财务账户类型、预算类别无法保存 | 静态类型 / 类别接口与 ID 接口顺序冲突。 | 创建、重命名、删除、刷新；全路由顺序检查。 |
| 员工自己的押金读取错误 | `/staff/my` 被 `/staff/:staffId` 截获。 | 真实员工 JWT 读取自己的押金。 |
| 固定资产新增失败 | 没有从登录账户写入门店；日期字符串直接交给 Prisma。 | 实际表单创建、刷新；API 创建、修改、删除及门店 / 日期断言。 |
| 会员奖励日期无法保存 | 日期控件返回日历字符串，Prisma DateTime 不接受；结束日需包含当天。 | 实际表单及两种数据库创建、修改、读取、删除。 |
| 库存批次接口报错 | Batch 没有 storeId 字段，改为通过 inventory 关系限制门店。 | 本店批次可见、其他门店不可见。 |
| 日历范围漏算当天交易、月末支出 | 日期范围使用 UTC 起点或结束日零点。改用雅加达营业日边界，显式带时区的时间仍保持原时刻。 | 当天凌晨、月末深夜与相邻月份边界。 |
| 有积分历史的会员删除时报 500 | 外键约束保护历史记录，却未给出明确业务反馈。 | 返回 409；会员与积分历史仍在，不删除财务关联数据。 |
| 员工积分规则误改会员规则 | 页面实际使用会员规则接口和字段。改接员工规则及五个员工积分字段。 | 保存、刷新；断言会员规则不变。 |
| 员工奖励目录接口不存在 | `/staff-point-rewards` 路径错误，创建又只接受 code=200。 | 改用共享 API；201 创建成功；描述、启用状态持久化。 |
| 停用员工奖励后无法重新启用 | 查询只返回已启用奖励。管理端可读取停用项；已删除奖励通过归档标记隐藏，保留兑换关联。 | 停用、刷新、重新启用；员工可用列表不包含停用项；删除后管理列表隐藏。 |
| 员工兑换申请名称空白 | API 返回嵌套 staff / reward，页面读取平铺名称。 | 从真实 API 映射员工名和奖励名。 |
| 16 个后台弹窗无法点击 | 遮罩 pointer-events-none 被内容继承。修正这些遮罩。 | 浏览器操作、全组件静态检查与弹窗按钮可点击检查。 |
| 员工首页卫生任务数量接口 404 | 首页调用的 `/tasks/my/pending` 未实现。增加按登录员工筛选的待办接口，并使用雅加达营业日期。 | 员工端逐页巡检和实际 JWT 请求。 |
| 员工兑换可能重复扣积分或只扣库存 | 兑换确认缺少状态转换和事务，申请信任客户端积分 / 奖励门店。 | 后端核对奖励成本、门店与状态；积分、库存、兑换状态和流水同一事务。并发确认只有一次成功，重复确认 / 已完成后取消被拒绝。 |
| 员工积分流水失败导致余额与记录不一致 | 发放、兑换、调整分步写入。改为事务，余额不足不做部分扣减。 | 数据库故障注入，余额、库存、状态、流水全部回滚。 |
| 已用积分到期后可能出现负余额或重复到期 | 到期扣减不检查余额，也没有原记录的原子处理标记。 | 到期扣减最多为剩余余额，重复处理无副作用。 |

## 测试范围

- 后台 113 个静态页面，员工端 20 个页面：实际构建产物、Chromium、真实 API 与独立数据库；检查脚本错误、空白页面和失败接口。
- 自定义类别、账户类型、预算类别、资产、会员奖励、员工规则 / 奖励的实际表单保存及刷新。
- 67 个路由模块的静态 GET 接口巡检；类别 / 类型生命周期、基础资料 CRUD、月末边界、员工积分与兑换的真实数据库工作流，在 PostgreSQL 和 SQLite 各运行一次。
- 17 组收银浏览器场景：连续收款、刷新 / 重启恢复、断网恢复、丢失响应、现金 / QRIS / 卡支付校验、多窗口等。
- 141 项防回归测试；173 项后台授权 / 交易回归；79 项实际 PostgreSQL 测试；51 项历史 SQLite 升级 / 保留测试。
- 四个应用 TypeScript 检查、三端翻译检查和生产构建。

数据库故障注入会刻意产生测试日志中的 `AUDIT_POINT_LOG_FAIL` 等错误；测试断言这些失败没有留下部分余额或库存变更。

## 仍需真实环境验证的边界

浏览器使用真实页面和本地真实数据库，收银打印相关测试使用测试打印适配器。物理打印机、收银机当前现场状态及尚未提供的 GrabFood / GoFood / ShopeeFood API，不能用这些测试代替真实硬件或平台验收。此前已打印但缺失的历史交易没有凭空补录；恢复需要原收银机的交易 / 小票证据。

这份检查记录表示已执行的覆盖范围，不承诺所有未执行场景都不存在缺陷。
