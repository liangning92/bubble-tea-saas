# Revenue selected date range

Baseline bfee6b70a192f7912ebd4507dafe4a8552cb9054; separate branch fix/revenue-custom-date-range. Only revenue UI and required revenue query dates; no expense/finance report changes, DB/schema/production/config writes, amount/tax/refund/cost formulas, publish or push.

Learned before fixing: TanStack Query keys must include query function dependencies (https://tanstack.com/query/v5/docs/framework/react/guides/query-keys); Date.parse interprets date-only strings as UTC and host-local strings inconsistently (https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Date/parse). Use authenticated store + immutable selected parameters as cache keys, distinguish pending/error/empty, and parse business calendar dates explicitly rather than via host timezone.

Verified defects: RevenuePage customDateRangeRef is never synchronized. Channel requests always today/week/month, custom counts fall back to month, footer always month, summary response current/previous/revenueChange is read as nonexistent today/week/monthChange. Async setters lack store/date race guard; preference read can replace a later manual selection. revenue router custom incomplete falls back silently, date-fns local boundaries depend on server timezone, explicit instants are expanded to calendar days. Daily grouping is also host-local.

Plan: keep explicitly labelled fixed today/week/month overview; give selected range its own channel table, summary and footer using identical parameters, with no misleading net/refund label or invented channel growth. Query by auth-store and selected range; disable invalid/custom-incomplete queries, reject invalid/ordered dates server-side, and ignore late preference reads after user interaction/store change. Preserve config preference saving. Date-only boundaries are Asia/Jakarta 00:00 through23:59:59.999; timezone-bearing instants keep exact meanings. Preserve Sunday week start and existing comparison amount calculations; only date construction changes. Missing-period endpoint defaults retained (by-channel today, summary month, daily current month-to-today); reject unsupported periods and malformed supplied values. Daily optional one-sided dates retained and WIB grouping follows filtered dates.

Verification: native App/router/Query tests for custom range, invalid/incomplete/ordered inputs, empty/errors/retry, date/store/preference races, fixed overview labels and three translations. Actual JWT Express revenue router/services with newly created /tmp SQLite equivalent of current Prisma schema tests ±1ms boundaries, cross-month, offset instants, validation, role/store scope and direct forged requests. No production database. Unit tests cover timezone independence and compatibility. Fixed local commit awaits independent review; no push.
