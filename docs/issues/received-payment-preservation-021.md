# 收银前拦截与已报告收款凭据保留

## 行为

现金为空、非整数、不足、超过限额、禁止找零却需要找零、订单低于最低金额或支付方式不可用时，收银界面显示具体原因并禁用确认。提交处理使用同一规则，绕过按钮也无法保存或打印。其他外部支付要求员工核对实际渠道和金额；QRIS 延续付款凭证或人工确认流程。这些都是员工报告，不构成支付平台到账验证。

普通现金先持久化本机订单、实收现金与找零，再打印。同步时先将收银凭据写入服务器，随后尝试订单入账。涉及会员/优惠等需要在线处理的订单，在提交订单前也持久化并上传员工的收款报告。已报告收款的提交被拒绝时保留原始身份进入 review，不能释放购物车后生成另一笔收款身份。

服务器的 received-receipts 接口独立于当前支付开关、班次和库存政策，保留原订单请求、员工、发生时间、报告金额、实收现金与找零。业务拒绝只影响正式订单入账，原凭据及原因保留。后台收银监控始终显示未入账凭据及合计，不受操作日志时间筛选影响，也不把待核对金额自动计入已完成营收。

订单成功后，凭据仍保留；只有正式订单的原始请求指纹及金额与凭据匹配，才从待入账列表消失。重复上传幂等，相同编号不同凭据拒绝覆盖。现金金额差异或请求冲突不会被当作已完成核对。

## 存储与权限

使用受保护的 receipts.pos. 配置命名空间，不改动数据库结构。保存凭据与监控事件在同一事务内，普通设置接口不能读写或删除凭据。认证和门店/员工归属仍需通过，收银员不能读取后台待入账列表；管理员与经理仅查询当前门店。修正配置后，收银机可按原订单号重试。

断网期间不能实时让后台看到本机交易；凭据会保留在本机，联网后优先上传。未包含原始快照的历史旧版订单仍须核实本机记录，不能用监控日志伪造补单。

## 验证

- 原生收银页面：空金额、现金不足、超过限额、禁止找零、外部支付未经渠道确认均禁用确认；直接调用处理函数也不能绕过空金额校验。
- 原生 IndexedDB：现金实收/找零持久化；连续销售、上传拒绝和响应丢失保留原始身份。
- PostgreSQL 与 SQLite 的真实 HTTP/Prisma：支付配置缺失仍保留凭据及金额；门店/角色隔离；并发重复上传只有一张凭据及一个监控事件；拒绝无虚构订单与库存变动；补齐配置后只入账/扣库存一次，原凭据保留。
- 实际后台页面：不存在正式订单时仍展示待入账凭据、金额、订单号和原因。
