## Explicit local-schema blocker before Windows
The existing approved installer WIP supports only nullable `Order.pickupNumber` and its nonunique index. Its authoritative catalog compares every current Prisma field; it never deletes user records or falsely certifies a missing field. The integrated model additionally contains nullable `Order.requestFingerprint` and `Order.requestReceipt`. Therefore an old local SQLite database missing those two columns is rejected by that WIP with `UNSUPPORTED_SCHEMA_COLUMN`.

An owned synthetic current-schema database with only those two columns removed reproduces this exact rejection. Evidence: `/var/folders/4_/zdfh8qfj3p7gv__dnkjh6f8h0000gn/T/pos-release-schema-b_p9ldb3/evidence.json`. This proves a code dependency, not actual installed shop schema. Learning/previous approved backup-and-additive-column scope: `manual-legacy-installer-upgrade-011.md`, `windows-upgrade-preflight-009.md`. Any narrow local helper extension must explicitly cover those two nullable TEXT columns after verified backup; no other columns, data cleanup or inventory mirror is proposed. Do not trigger a Windows candidate claiming existing-db compatibility until the exact local scope is resolved and validated.
