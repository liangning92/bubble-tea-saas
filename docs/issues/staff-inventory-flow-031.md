# 员工库存操作与消耗预警

## 问题与根因
员工库存页以物料列表为主，采购仅限后台，出库原因与接口不一致。销售自动扣库与员工领用扣库重复；现有盘点推导分析不能代表每日员工出库。

## 学习与方案
采用 Prisma interactive transaction 将收货、流水及成本更新原子提交，并以唯一操作标识避免网络重试重复写入。官方说明：https://www.prisma.io/docs/orm/prisma-client/queries/transactions 。本项目继续使用已安装的 Prisma 5 API，不迁移 ORM 版本。

以用户确认方案为准：四个员工入口、供应商可空、整单收货、员工盘点提交管理审核；销售只保存不可变配方快照，实际出库对比理论消耗，每日按雅加达营业日预警。新口径启用时间隔离旧数据。

## 已实现
- 员工库存首页四个入口；采购供应商选填、包装换算、整单到货确认；直接出入库带可恢复的请求标识。
- 员工发起全部/指定物料盘点，保存观察、提交冻结，后台审核差异；条目顺序稳定，同店未结束任务互斥。
- 销售理论消耗使用销售时配方快照，独立于实际出库；未制作退款冲销理论，已制作退款保留；旧销售仍使用原始已认证扣库证据处理退款。
- 按雅加达营业日统计领用、报损、过期、其他、加工出库；默认 10%/20% 阈值，闭店后持久化预警，补算停机期间营业日及延迟同步/退款影响的历史日期。
- 离线订单同步传输不可变消耗快照；缺少快照/配方时显示数据不完整。新口径启用时间隔离旧数据，切换日不预警。
- 新流程授权给 staff 员工及已有管理角色。收银员 cashier 权限保持原样；自动审批拒绝了额外扩展该角色权限，未纳入此次实现。

## 验证
- API、后台、员工 App TypeScript 无输出类型检查通过。
- 后台及员工 App 中/英/印尼语翻译检查通过。
- 任务专用 PostgreSQL 与 SQLite 各 39 项回归通过，含成本、单位、盘点、退款、跨店接口、原子收货失败、重复请求、预警阈值和晚到退款补算。
- 旧 SQLite 真实表结构升级验证通过：先备份，再将供应商改为可空，保留采购明细和库存余额，重启可重复验证。
- PostgreSQL 从改动前结构执行迁移脚本通过，仅使用临时 Unix socket 测试数据库。
- 浏览器手机视口 390px、桌面 1440px：采购登记→整单收货→出库→盘点提交→后台审核，以及差异预警与三种语言通过。截图在本任务 output/inventory-flow-page 中。

## 可复现检查
```sh
node scripts/check-employee-inventory-flow.cjs
```
该脚本创建新的 /tmp/bubble-inventory-flow-* 数据库及独立 Prisma 客户端，不执行构建，不读取实际门店数据库。旧结构样本固定为 c74ecfa524d7c0f108be9310e397e6aaff0a9b96 的 schema.sqlite.prisma。
浏览器检查使用 server/audit-flow-tests/page-server.ts 生成合成门店，Vite 开发预览代理指向本机测试接口，再运行 tests/stoploss/inventory-flow-page-check.cjs；每次重跑先生成新门店数据。
