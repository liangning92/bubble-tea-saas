## 已确认存在消费缺口，尚未修复

这些字段能够写入配置，以下问题是“没有按设置使用”，不能当作“数据库没保存”。本次不擅自引入收银、税务、结算与交班政策。

| 设置/范围 | 代码证据与实际限制 | 优先级 |
| --- | --- | --- |
| POS 渠道营业时间、最低消费、佣金 | POSSettings 保存 channelSettings.availableHours/minOrder/commissionRate；POSPage 只使用 enabled/name/icon/color。渠道主表另有 availableHours/minOrderAmount/commission；POS 设置未同步这些字段。isChannelAvailable 仅有定义，无调用 | 高 |
| POS 交接班 requireReconciliation、showSummary、cashDifferenceLimit | POS 中只有默认值和配置读取，未见以这三项控制交班界面或校验；服务器 posCash、POSOfflineOperationService 也未以它们限制交班。主管确认和小票 receiptItems 有单独消费者，不能一并说无效 | 高 |
| POS 错误音、新订单音 | soundSettings.error/newOrder 被读取；实际事件只调用带设置的 keypress/orderComplete；其余 playSound/错误提示未接入这两个配置 | 中 |
| POS 税费“在小票显示” | taxSettings.showOnReceipt 被读取但未用于打印参数；打印和收银税额存在独立配置。不能据此推断税额计算无效 | 高 |
| POS 支付费率与结算周期 | paymentMethods.rates、settlementCycle 在后台可保存，POS/服务端无相应费用计算或结算消费者；支付开关、默认方式、最低金额、现金上限、找零已有真实校验 | 高 |
| POS 扫码启用/类型、屏幕亮度 | scannerEnabled/scannerType/displayBrightness 有配置与读取，但未见扫码输入禁用、串口切换或系统亮度调用；不能把仅保存成功当作设备实际生效 | 中 |
| 财务 enableTransfer/cashOnlyMode/accountingMode | 除设置页外未见 enableTransfer/cashOnlyMode 业务消费者；accountingMode 只在设置页切换其他开关。账户/预算/固定资产入口另有 show 消费者，本次已修读取 | 中 |

## 不能误判为缺陷的情况

- 财务报表使用原始收据 checkoutTaxAmount，不用当前税率、免税分类、计税比例重新计算历史订单。设置变化不应回写历史税额；本次不修改这一规则。
- 财务模块入口开关属于显示配置，不代替后台权限检查。
- KDS 的排序、超时、刷新间隔、声音、渠道标识、计时器都有读写及 UI 消费者，未发现上述“对象当数组”的错误；尚未逐项更改线上值验收。
- 店铺信息、员工权限、卫生配置、消息渠道走各自读写接口；在本次静态审查范围没有发现相同的漏回填错误，不代表所有设备、所有角色和所有状态已通过真实验收。
- 打印机路由、小票模板/字段、副屏外观存在独立消费者；打印机、钱箱、扫码枪、Windows 自动升级需要设备验收，Web 页面和单元检查不能代替。
