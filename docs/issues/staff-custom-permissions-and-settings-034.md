# Custom employee permissions and unified settings

Settings → Employee Permissions now lets the administrator create named roles, select permissions, assign employees, and review the last thirty changes. Roles start from manager, cashier, or staff templates and can restrict the capabilities available to that template. Administrator-only actions remain protected. Existing employees keep their system permissions until explicitly assigned a custom role.

The policy is stored per store in a protected Config entry. Updates are transactional, reject stale revisions, validate role names and permission keys, and create an audit record. Assigning a different base role invalidates existing login tokens; subsequent authenticated requests read current custom permissions. Removing an assignment restores the captured original system role. The existing employee-detail role editor removes a custom assignment atomically when an administrator explicitly changes the system role.

The API denies missing and unclassified permissions for assigned custom roles. Employee personal routes preserve ownership and store boundaries. Invalid stored policies fail closed for employees while administrator access remains available. Already-paid receipt evidence retains its existing protected ingestion path to avoid losing financial facts. Offline clients cannot obtain immediate permission revocations while disconnected; this change does not claim physical POS or offline hardware acceptance.

Admin navigation reflects assigned custom permissions. Read-only finance and salary roles cannot use the corresponding mutation controls, and direct API mutations are independently blocked. AI permissions now use the same settings tabs and visual components as the other settings modules; saving AI settings still creates a disabled draft.

Validation: all-app type checks, API/Admin builds, i18n checks, PostgreSQL HTTP scenarios (368 requests), SQLite HTTP/manual scenarios (393 requests), and actual browser role creation, checkbox persistence, assignment persistence, history, read-only controls, direct API rejection, and settings deep links passed. Additional cases cover same-session revocation, stale saves, role restoration, protected configuration, cross-store assignment, foreign personal task access, notification scoping, and invalid-policy handling. Browser mutations used isolated fixtures, not production employees.
