## 原因与证据界限

缺少支付配置会返回 PAYMENT_CONFIG_UNAVAILABLE，其 JSON 正文恰为 51 字节，与日志相符；ORDER_IDEMPOTENCY_CONFLICT 也可能产生相同长度。因此缺少配置是最符合现有证据的解释，不能将长度当作错误正文的直接证明，也不能证明此前没有配置删除重建。

历史 POS 代码曾将任何提交异常转为本地待同步订单，然后打印和清空购物车。这与本次监控及用户看到的打印行为一致；当前设备实际版本尚待核实。后续代码已禁止 HTTP 拒绝转为成功离线单，并采用先持久化结账身份的流程。

目前没有小票、原始请求或收银机 IndexedDB 数据，不能认证该笔交易已经收款，也不能用操作日志补建财务订单。恢复需先保留并核验收银机本地记录，避免重复收款、扣库存及入账。
