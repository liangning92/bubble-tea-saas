# 全面检查问题修复（2026-10-07）

依据同日全面检查报告实施，保留已部署的培训功能、订单原始回执和离线保护。代码修复完成后，正式发布仍须通过匹配源码的 CI、Windows 升级与线上健康验证；没有通过验证的安装包不能进入更新渠道。

| 项目 | 修复结果 |
|---|---|
| 01 前后端版本不一致 | 健康接口提供源码版本与能力；安装包发布要求正式后端同 SHA |
| 02 部分退款整单冲销 | 按商品数量分配折扣和税额；限制剩余可退量；未制作整单按原库存流水返还 |
| 03 审批、退款及库存事务 | 审批状态、退款、库存、积分和现金事件在同一事务提交 |
| 04 门店资源越权 | 补齐供应商、盘点、工资、员工、产品和费用归属；保护内部配置和业务回执 |
| 05 成本及配方泄漏 | 普通产品响应递归去除成本、BOM及工艺信息 |
| 06 盘点覆盖后续库存 | 基于库存流水序列及观察时点计算增量，审批不覆盖盘点后的收发货 |
| 07 营收金额及订单状态 | 统计实际收款，扣除已批准退款，排除挂单和未付款订单 |
| 08 历史税额重算 | 保存结账税额；旧税额缺失显示不可确定，不按现在税率回填 |
| 09 会员余额并发及重试 | 行锁、余额原子变更、事务流水及请求回执；前端丢失响应保留请求号 |
| 10 错误数据库备份 | 正式定时任务改为 PostgreSQL 一致性备份，同时备份上传媒体；恢复演练通过 |
| 11 生产依赖漏洞 | 两套生产依赖扫描为零；SheetJS、路由、Electron升级；镜像锁文件安装 |
| 12 WIB 时间 | 日、月、工资、报表及订单号按 UTC+7，避免主机时区影响 |
| 13 工资硬编码与日期 | 使用员工明确配置的基本工资，允许零，不给未配置员工推算工资；月末完整范围 |
| 14 自动支付未就绪 | 缺凭证时明确不可用；禁止模拟支付；真实开通仍需要商户凭证和回调令牌 |
| 15 QRIS 绑定及回调 | 校验真实订单、门店、金额和状态；回调与订单事务一致；重复回调修复历史中断 |
| 16 健康接口虚假成功 | 实测数据库和 Redis，超时或故障返回 degraded/503 |
| 17 基础设施暴露 | DB/Redis仅本机端口，服务自动重启；单主机高可用及异地目标仍需额外基础设施 |
| 18 部署文档陈旧 | 固定源码与镜像、配套迁移、备份、健康验证及回滚流程见部署说明 |

现有业务缺口：四类真实批量导入（保留全部行、逐行错误、重复请求去重）；叫号管理与显示端共享门店日队列，新版已付款订单关联叫号；员工假期余额真实读取和保存；周期费用存储在服务器，定时生成、并发去重，桌面副本不执行财务任务。

外部依赖和规划功能：GrabFood、GoFood、ShopeeFood 按用户要求预留适配接口并显示待接入；供应商门户、顾客自助端和真实 AI 执行没有实现为模拟功能。跨平台支付账单自动对账需要提供真实账单/API。异地备份必须有实际目标，不能将同盘副本宣称异地备份。旧税务数据和基本工资缺失必须由业务人员补充真实凭据，不能编造。

本机已完成验证：125 项专项测试、165 项审查测试、78 项隔离 PostgreSQL 测试、51 项 SQLite 测试、10 项安装升级辅助程序测试、4 项预检测试；四应用构建和类型检查、三语检查、Electron 编译；真实 HTTP 在 SQLite/PostgreSQL 的断线重试、并发幂等和事务回滚。正式备份恢复及迁移演练确认 105 张原有表的所有原字段数据一致。

实际收银设备尚无远程会话，Windows CI 测试通过也不能替代门店打印机、钱箱及设备安装验收。验证证据保存于工作区 recovery，正式上线结果另行记录。
