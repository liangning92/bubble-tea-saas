# 购买时段分析与押金应收金额

营收页面的渠道营收图替换为购买时段分析：单日显示 24 小时分布，多日显示日期 × 小时热力图，点击日期或色块查看当天分布。峰值卡片显示具体日期、小时和人次，并列最高可展开。保留财务汇总及渠道明细。

人次累加成交订单的 customerCount，未记录或非正数按 1 人；不代表去重顾客。已退款订单仍代表发生过购买，未成交和取消订单不计。雅加达 WIB；延迟同步订单使用与原请求指纹及金额相符的收银凭据时间，历史订单使用创建时间。范围最多 366 天，空日期和小时填零；分析读取失败提供重试，财务汇总继续显示。

押金表单“合计”改为“应收押金总额”。选择或切换规则时自动填入规则金额，仍允许按员工约定修改。移除固定 500000 示例。保存仅建立应收目标，不直接扣款；已收、已退金额另行记录。

验证：四个应用类型检查，后台三语言校验，API/后台构建；独立 SQLite/PostgreSQL 的真实鉴权 HTTP，WIB 起止毫秒、人数与订单数、退款及未成交订单、旧人数回退、跨门店、延迟同步/上传日不重复统计、收银凭据金额不符回退、空数据、无效/超长日期、鉴权。真实后台页面测试日期切换、热力图选日、时段峰值及并列、请求竞态、语言、权限、错误与重试。真实押金表单选择 Rp 300.000 和 Rp 500.000 规则、清空规则、保存后已收为零、刷新及员工 App 联动。

所有测试写入自建临时数据库，公网页面验证也将 API 拦截到临时数据库，未建立任何生产测试订单或员工押金。
