Learned before implementation: official PyInstaller6.11.1 usage supports a self-contained onefile Windows helper, so staff need no Python/SQL commands (https://pyinstaller.org/en/v6.11.1/usage.html). SQLite VACUUM INTO creates a consistent snapshot but requires explicit durable flushing/verification; it cannot run within an open transaction (https://www.sqlite.org/lang_vacuum.html). BEGIN EXCLUSIVE/IMMEDIATE prevents concurrent writes while narrow DDL is checked and committed (https://www.sqlite.org/lang_transaction.html). Installed NSIS customInit precedes old-process shutdown/uninstall; customCheckAppRunning can perform a second check without killing POS; customHeader can define .onInstFailed recovery before the install section.

Plan: interactive staff confirmation that no payment is in progress and POS was normally closed; silent legacy upgrades refused. Native helper refuses a running BTPS/BubbleTeaPOS/local node API, ambiguous profile DB, unsupported schema, failed integrity/foreign keys or backup. It locates only the current Windows user's supported profile database; Mac/unit fixtures are not store targets. Compare all expected columns against fresh authoritative SQLite catalog, allowing only missing nullable pickupNumber. Before DDL, create/fsync/integrity-check a consistent DB snapshot and verify all historical rows plus a complete old application backup on the old application's volume. Recheck processes and acquire an exclusive SQLite transaction; add only column/index if absent; compare historical rows again and commit. DDL failure rolls back and keeps original app/data; no background startup migration.

Application replacement failure restores the verified old program directory/installation records from backup, keeping the additive nullable column if it was already committed. Never restore a stale DB snapshot over live/new orders. Preserve backups/failed-new application files for recovery; no delete/reset of user history. New installer still refuses unsupported/multiple-profile/running cases instead of guessing. Upgrade folder changes are not allowed to redirect the old-app rollback target. Future automated updater activation stays disabled; staff launch the installer themselves.
