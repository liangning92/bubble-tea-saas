# 三端按路由加载页面（2026-10-08）

原先 App.tsx 静态导入全部页面，使登录页也包含报表、费用、库存及员工管理等页面代码。三端现改用模块顶层 React.lazy：后台 125 个页面、POS 9 个页面、员工端 21 个页面。现有路径、鉴权和重定向保持不变；别名导出的员工积分页正确映射命名导出。

Suspense 提供现有三语言 common.loading 提示。后台主内容和员工端页面内另设边界，保留侧栏/底部导航；路由过渡也可能保留前一页直至模块加载完成。后台 createBrowserRouter 内加入既有 ErrorBoundary，模块下载失败显示恢复控件，不出现 React Router 默认开发者错误页。不自动刷新，避免打断尚未完成的收银操作。

Rollup 已自然生成独立页面及共享依赖文件，xlsx 和图表代码只在使用页面时加载，不用粗粒度 vendor 分组把它们重新塞进首屏。当前主入口：Admin 741.34 kB、POS 493.13 kB、Staff 322.57 kB（Vite 输出）；这些是单个入口大小，不等于完整首屏下载量。POS 还存在约 415 kB 的共享块，不能把入口降低比例冒充整页或运行内存降低比例。

验证：
- 三端 TypeScript + Vite 构建通过，i18n 检查通过。
- Chromium 加载三端实际生产产物：登录页仅请求登录模块、不下载业务页面；未登录访问受限页跳回登录且不下载受限模块；冷加载有提示；延迟模块下载时导航保留；切页按需下载；深链接刷新可用。
- 中断后台注册页模块请求，显示错误恢复界面且不自动刷新。
- POS 生产产物 file://、浏览器离线时，直接进入诊断并切换会员注册仍能读取本地模块。该项验证本地资源加载，不冒充 Windows 安装或打印机验收。
- 146 项 stoploss 回归通过；实际 IndexedDB 的现金校验、连续十笔离线销售、恢复同步和多标签竞争通过。
- 浏览器检查加入 CI，所有测试请求限定本地合成环境。

发布时旧浏览器标签页可能仍持有旧文件引用；下载失败由手动恢复界面处理。桌面必须使用包含所有 dist/assets 文件的新安装包，不可只替换入口 JS。
