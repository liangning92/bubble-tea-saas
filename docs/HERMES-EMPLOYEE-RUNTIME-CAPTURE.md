## Existing host contract, not a new business protocol

Mainline owns `server/src/services/teamAgentBridge/employeeRuntimeContract.ts` and `EmployeeRuntimeHostPort`. The child consumes its revised `employee_work_trace_v1` ticket (sealedUserContent/instruction/inputContextHash/tools/isolation/model), and transports `recordInput`, `recordResponse`, `executeTool`, `recordOutput`, `markUnknown`; mainline resolves `begin(grant,scope,sources)` from trusted authorization. Neither ticket nor proof is accepted as a model tool argument. Stdio adds only framing `{protocol,method,params}` and host response `{result}`; `finished` is child termination metadata, never outbound authorization.

Deploy-time injection: installed Hermes venv executable, source checkout and expected commit SHA, canonical isolated writable root, provider base URL and credential supplied over the private child pipe. Paths/endpoints are configurable for moving this child to a cloud host. No download, package installation, tunnel or credential provisioning is performed. The parent must own/authenticate the child process and apply its existing schema validators; do not expose this internal pipe as a public proof/enrollment endpoint.

## Real multi-round execution

`run_ticket` calls `run_employee`: **full Hermes execution**, actual `run_conversation`, backend-issued employee tool catalog, captured real tool args/results plus all subsequent provider input bytes and complete raw JSON/SSE provider responses. Each turn's actual SDK wire goes through `recordInput` (actual input hash and tool schema binding) before sending. `response_observed` parses a complete response and persists `recordResponse` before a requested tool can execute. Tool handler matches name, parsed arguments, call ID and ordinal against that response and calls `executeTool`; only its exact `value` enters the next model input. Returned `sources` must have been derived and stored by backend, never selected by model arguments. Current test tools are synthetic; actual native tool composition is mainline's remaining integration responsibility.


The child loads installed source SHA `a7198a8855ad98681114ff5138eb01fe132a62e7` for this acceptance; runtime refuses another configured SHA. It does not edit that installation. Source SHA identifies the trusted checkout; it is not an OS sandbox or proof that arbitrary modified source code is harmless.

## Isolation and evidence

- Fresh child process and empty HOME; inherited secret/env variables rejected or cleared by launcher, preloaded Hermes modules rejected. HERMES_HOME points to `isolatedRoot/executions/<execution-hash>/profiles/employee_work`, never the private default profile. Session is the backend-issued `employee_work_<64hex>`; profile and used-session directories are created exclusively. Reusing an execution/profile/session after restart is rejected before model access. Backend allocates a new authorized ticket only after reconciling unknown work.
- Before any Hermes import, a child-only no-I/O env loader disables source/profile/managed dotenv and external-secret hydration. Secret registry discovery returns an empty catalog; fetching/registering external sources is denied. A permanent Python audit fence denies dotenv/credential reads, external-secret imports and environment mutation. Effective HOME/HERMES_HOME, module identity and full environment snapshot are checked after import/init and at each model/tool boundary. Only the exact session variable and idempotent writes of pinned values are permitted. Public terminal defaults are pinned from the installed code before tools run (Hermes otherwise mirrors them during its first non-terminal tool call); this enables no terminal tool and accepts no inherited/user terminal settings. Mapping replacement/bypass is detected, restored to the original compartment for cleanup, and marks the execution unknown. These are trusted-child controls, not an OS sandbox against arbitrary native code.
- No copied memory, SOUL, AGENTS, history, inventory session, user auth file, plugin or cron. Memory namespace matches compartment key, but memory itself is disabled. Backend owns current task/audience/role/grant version and compartment freshness; the child cannot grant permission merely by repeating a compartment string.
- Entire actual model request bodies are captured, including system, user and assistant/tool messages; no text truncation. Complete raw provider responses are captured before tool execution. Tool arguments and exact returned data/result hash are recorded by the registered runtime handler. Sources must be derived and reauthorized from actual tool/source reads by mainline, not the model's source list. The backend-issued catalog is the entire tool surface; built-in terminal/browser/SQL/memory tools remain disabled. Tool RPCs serialize even if Hermes schedules parallel tools, keeping trace versions ordered.
- Output must exactly match the last complete provider response, with locally computed SHA256. Hermes-generated fallback prose after empty output is not a provider-observed completion. A model string containing `proof`, `decision:allow` or source labels remains only untrusted output text. `complete` describes raw observation completeness, never `CommunicationPolicyPort.admitOutput`. Trusted host source receipts and traceVersion are retained alongside tool result hashes for private audit; only their value enters the model.
- Unrecognized provider destinations/async requests, tool-surface mismatch, failed source read, empty output, incomplete capture or byte cap leave the observation incomplete. Known model-metadata probes are intercepted locally with 404, fully listed separately, and never forwarded. No financial/employee data is sent to such probes.
- `recordInput` is one-shot per turn. A subsequent normal turn is allowed only after the previous response was recorded and all matched tools returned persisted receipts. Lost response, repeated SDK attempt, rejected input/tool or failed output persistence marks unknown; no second send of that uncertain turn, new execution or fallback to manager context. A partial SSE cannot authorize a tool. If markUnknown itself cannot persist, report an unconfirmed host failure for backend reconciliation.

## Running and framing

Explicit launcher (not automatically executed by imports):

```text
<configured-hermes-venv-python> -I -B scripts/hermes_employee/host_stdio.py
```

Host writes first line `{ticket,config}`, then handles child port method frames and replies `{result:...}`. Input is recorded before the sender; the same actual captured request is available in `finished.params.observation`. No default profile or real credential is discovered automatically. `config` keys are `isolatedRoot`, `hermesSource`, `hermesExpectedSha`, `providerBaseUrl`, `providerCredential`; the root must be canonical (on macOS `/tmp` commonly resolves to `/private/tmp`). Pipe credentials must not be logged. Library stdout is redirected away from protocol framing; log storage remains private runtime data.

The backend must persist all observation/source/ACL metadata and final output hash, apply current whole-audience ACL and protected-class policy, and send only through the existing transactional bridge. It must not send `finished` text directly to employees. Host RPC deadlines/process supervision are required: a dead host/pipe/child is unknown, never a replay permission. Child model loop is bounded to three iterations and a 30-second run budget; a longer operating task must settle the current execution and be resumed only by backend authority, not shared history or automatic retries.

## Multi-round operating loop and remaining composition

The implemented child keeps the same executionId/compartmentKey/task/audience binding throughout one isolated real `run_conversation`. It uses the mainline recordInput/recordResponse/executeTool fields (turn, expectedTraceVersion, toolCallId, callOrdinal). The backend must validate subsequent history against its actual persisted responses/receipts, including any Hermes argument-JSON normalization, and deny unrecorded context. Any gap, stale permission/version or provider unknown blocks later steps and outbound. Full raw response observations are returned on completion; the host must retain them privately for audit in addition to the incrementally persisted typed response.

Minimal operational loop: read authorized task/current employee messages → ask a natural-language operational clarification through native outbound admission → persist waiting state on original task → employee reply becomes a new execution in the current authorized compartment → read feedback → update the same native task/report. Finance/private-source projection remains denied, independent of what an employee says. Tools are limited to authorized native operations; no terminal/files/arbitrary web/SQL or manager-memory access. A message-send tool requires admission of the actual model tool-call text before the native send transaction; final text capture alone is insufficient. Mainline owns these canonical schemas and atomic trace/source/state records; child code does not invent a second task or permission protocol.
