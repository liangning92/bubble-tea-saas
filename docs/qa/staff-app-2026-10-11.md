# Employee app workflow repair

## Reproduced problems

- Home was labeled Attendance in the persistent navigation. Salary had a route and working data but no home shortcut. Common work shortcuts appeared after monthly metrics.
- The weekly grid started Monday but read the Sunday key for its first cell. Both schedule and swap forms assumed a fixed list of shifts rather than store configuration.
- Hygiene offered Complete for pending tasks while the server accepts completion only after Start. In-progress tasks disappeared from the pending list; there was no required-photo input, no action error feedback, and approved/review states were omitted.
- Announcements read notifications rather than active store announcements. Text was truncated without a detail view.
- Home and several work pages swallowed failed reads and presented zero counts or empty lists. The current attendance state survived a null response.
- Device/server timezone affected day and week boundaries. Local training checklist data was shared across employees using the same device.
- Password form allowed a password shorter than the backend policy; successful change invalidated the session but did not return the employee to login. Forgotten-password link did nothing.
- Inventory category filters used translated strings instead of stored category values. Reimbursement types silently reverted to defaults when the server returned no enabled types.

## Changes

Home and salary/work shortcuts are visible together near the top; shortcuts also remain usable when overview data fails. A fixed Home button, route fallback, and mobile safe-area padding keep navigation available. Work pages show explicit loading/failure/retry states. A request timeout and 401 logout flow replace silent expired sessions. Store shifts supply names and times in schedule and swap forms. Hygiene has Start, photo attachment, submit/skip forms, reload after mutation, and persisted status labels. Personal announcement reads are store scoped. Dates use Asia/Jakarta. Training local records are scoped by employee.

## Verification

- Frontend production build and backend TypeScript compilation.
- Eight isolated tests: staff schedule Monday/Sunday/custom configuration, invalid date, WIB attendance bounds/latest record, personal permission routing, cross-store announcement rejection, and existing timezone checks. The isolated test configuration never initializes a real test database.
- Local browser with synthetic HTTP fixtures: login, Home shortcuts, salary detail, custom shift schedule, Home return, hygiene Start → Complete → awaiting approval, request log inspection, and failure/retry navigation.
- Existing authenticated production account: read-only inspection confirmed salary data is available at /salary; its missing navigation entry caused the discoverability problem. No production attendance, leave, hygiene, inventory, or payroll records were created or changed for this audit.

Camera scanning, physical inventory movements, real attachment upload, and administrator approval were not submitted against production during this audit.
